# 倒立摆工程分层架构重构计划

## 背景结论
- 本工程是 **CubeMX 6.18 生成的 CMake 工程**（非 Eclipse .project），源文件清单在根 `CMakeLists.txt`（用户区，CubeMX 不会覆盖），重构只需移文件 + 改这一个文件。
- `Core/` 里的 CubeMX 生成文件**必须留在原位**（`.mxproject` 记录了生成清单，移走会导致下次 CubeMX 重新生成时重复写出一套文件）。`.mxproject` 不追踪 8 个手写模块，移动它们对 CubeMX 无影响。
- 所有 `#include` 都是裸文件名（靠 include 搜索路径解析），**源码内容预计零修改**。

## 目标目录结构
```
Inverted_pendulum/
├── Core/            # CubeMX 生成，原位不动
├── Drivers/         # HAL/CMSIS，原位不动
├── App/             # 应用逻辑层
│   ├── mode.c/h         # 模式状态机（菜单、直立环调度）
│   └── angle_sensor.c/h # 摆角传感器标定换算
├── Composite/       # 复合层：跨层组合模块
│   └── serial.c/h       # 串口/蓝牙调参（UART收发 + PID命令桥接 + VOFA+协议）
├── Middleware/      # 可复用算法库
│   └── pid.c/h          # PID 算法（位置式+增量式）
├── BSP/             # 板级驱动层（直接操作外设句柄）
│   ├── motor.c/h        # TB6612电机 + TIM4编码器
│   ├── oled.c/h         # SSD1306 OLED (I2C1)
│   ├── oledfont.c/h     # 字库数据
│   └── key.c/h          # 按键EXTI + 电位器ADC
└── CMakeLists.txt   # 更新源文件列表与 include 路径
```
依赖方向：App → Composite → Middleware → BSP → Core/HAL（App 也可直接调用下层）。

## 实施步骤
1. **git 存底**：`git init`，确认 `.gitignore` 覆盖 `build/` 等产物目录后提交当前状态作为还原点。
2. **移动文件**：按上表创建 4 个目录，用 `git mv` 移动 8 对 .c/.h（共 16 个文件）。
3. **更新根 `CMakeLists.txt`**：
   - `add_executable` / `target_sources` 中 9 处源文件路径改为新位置；
   - `target_include_directories` 用户区新增 `App`、`Composite`、`Middleware`、`BSP` 四条 include 路径。
4. **检查外围配置**：
   - grep 全工程确认无遗漏的旧路径引用（如 `Core/Src/motor`）；若个别文件存在相对路径 include 则一并修正（仅路径，不改逻辑）；
   - 检查 `.vscode/c_cpp_properties.json` 是否硬编码了 includePath，需要则同步补充。
5. **编译验证**：重新运行 CMake 配置 + `cmake --build build/Debug`，确保 0 error 0 warning 产生、elf 正常生成；`git diff --stat` 确认源码内容无改动（只有 rename）。
6. **新增简短 `README.md`**：记录分层规则和"新文件该放哪"，方便后续维护（这不算改代码）。

## 明确不做的事
- 不动 `Core/`、`Drivers/`、`cmake/stm32cubemx/`、`.ioc`、`.mxproject`；
- 不修改任何源码逻辑（serial.c 死代码、key.c 里的电位器函数、pid↔serial 循环调用等遗留问题保持原样，仅记录在 README 中待后续处理）。

## 风险与回退
- 最大风险是 CMake 路径写错导致编译失败——通过第 5 步编译验证兜底；任何异常可用 git 还原到重构前快照。
